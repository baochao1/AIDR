# 插件管控加固与验收

## 已完成

| 审查问题 | 当前处理 |
|---|---|
| 进程显示运行，但事件流已断 | Agent 重试打开同一个实例的事件流，事件序号在重连前后连续。状态独立报告建流、收数、重连、背压和接口不支持，附最近一次已接收事件时间。Windows 界面展示采集状态。 |
| 已安装或回滚版本可能发生变化 | 从通过验签的 ZIP 导出每个文件的摘要并持久化。检查安装目录时拒绝缺失、多出或修改的文件。复用缓存目录、启动和回滚前执行校验。旧记录缺少校验清单时，必须先重新从管理端取得受信制品并校验，再启动。 |
| 慢管理请求影响本机监督 | 管理端 check-in、制品下载改为独立后台操作。运行中的每个插件独立探活。安装提交、启动判定、停止及版本切换仍由协调器串行。 |
| 进程反复崩溃或启动失败 | 登录同一个 Agent 期间，每组件使用 60 秒故障窗口。窗口内达到 5 次失败就进入重启限流，等待旧故障滑出窗口或新策略重置。失败同时有指数退避。故障包括运行后退出、连续探活失败及启动失败。 |
| 管理端看不到期望版本或采集状态 | 状态包含实际版本、期望版本、进程状态和独立采集状态。通过管理端 API 可查最近收数时间。 |

## 实测

- Windows amd64 上 go test ./...、go vet ./... 通过。
- Windows 本机和 Ubuntu WSL2 的全量生命周期脚本退出码均为 0。包含两个原生 IPC 组件同时无 TCP socket 收数、正常升级、失败回滚、强杀恢复、离线队列恢复。
- 专项测试主动关闭首条 gRPC 流，确认 Agent 重新建流。重连前、后的事件都入队，序号分别为 1、2，且 ACK 和已入队记录一致。还验证修改已安装入口后拒绝校验和复用，以及重启预算窗口过期行为。
- 按 Windows、Linux、macOS 与 amd64、arm64 六目标执行 Go 构建。实际运行覆盖见上述平台。

## 下一批仍待做

- 正式服务身份、目录 ACL 和组件最小权限隔离。当前摘要复核发现安装文件变化，仍依赖 Agent 状态及安装目录的系统权限保护。
- 管理端配置 revision、插件应用回执，以及配置失败后的保留旧版本策略。
- 每组件独立升级事务、全部断点恢复验收、阶段清理及停机确认。当前协调器还串行本地安装、探活启动确认和进程切换。
- 重启预算跨 Agent 重启持久化。插件未收到 ACK 的事件重放与厂商源 ID 去重，也需进一步定义。
- 采集状态表示最近的流和终端接收情况。平台最终送达仍通过管理端接收记录核对。长期空闲或半开链路的主动探测及告警阈值待定。
