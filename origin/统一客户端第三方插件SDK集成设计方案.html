00设计摘要

一句话方案：第三方 SDK 一律以「独立适配进程 + 统一适配层」形态接入统一客户端，GUI 不直连任何 SDK，日志采集复用统一文件采集器，指令交互收敛为一条控制面指令通道。
设计域核心结论优先级
集成形态方寸 AIDR 与安天 AV 引擎均不进宿主进程：由 Supervisor 拉起独立适配进程，SDK 库只加载进适配进程内，崩溃/泄漏/升级被进程边界隔离P0
适配层适配进程对外只暴露统一插件契约（HELLO 注册 / 文件交付 / 指令响应 / 心跳），SDK 私有 API 不外溢；AV 与 AIDR 适配器按同一契约实现，可替换可扩展P0
GUI 融合UI 独立进程，只通过本地回环 API 读写 Agent Core 缓存态；插件状态卡 / 统一告警流 / 隔离区 / 任务中心四类融合组件；UI 崩溃不影响防护P0
日志采集零新增通道：SDK 事件由适配器落盘为 JSONL / 快照文件，完全复用《日志采集专项设计》三类 Reader + 三级队列 + WAL 管道P0
指令交互平台 → WSS → Agent Core → IPC → 适配器 → SDK API 单链路；扫描/病毒库升级为异步长任务（task_id + 进度事件 + 回执），指令可审计可超时可取消P0
插件规范对齐采纳 iNode 插件系统声明式配置（plugin_config.jsonc）与 ZIP 打包安装流程，扩展 Security / DataSources 两个安全区块；插件类型采纳 ui / background / mix 三分类，AV / AIDR 适配进程为 background 型；插件自治原则保留但收紧安全基线（禁自建上报通道、网络通信须声明）P0
升级与资源病毒库 / AI 模型独立升级通道 + 失败回滚 + 灰度；扫描任务受 CPU/IO 配额约束，支持游戏/演示模式全局抑制P1
共存与兼容与第三方 AV 共存策略（被动模式）、OS 版本矩阵、驱动级协同例外说明P1
本方案是端点三层架构（统一管控平台 / 网关层 / 统一客户端）中「统一客户端」容器层的集成设计。终端侧自研 Supervisor、Rustinel、文件采集管道均沿用既有文档结论，本文只新增「第三方 SDK 如何进来」这一层，不重复上游内容。

01集成背景与 SDK 对象分析

明确统一客户端的容器定位、两个第三方 SDK 的能力边界与接口形态，以及闭源二进制带来的集成约束。

1.1 统一客户端的容器定位

统一客户端是端侧唯一的用户可见实体，内部按六大模块组织；AI 防护（自研 Supervisor + Rustinel + AIDR）是其中「AI Agent 防护」模块的落地形态。本方案把方寸 AIDR、安天 AV 作为第三方能力供给方接入，统一客户端自身的模块划分不变：

模块能力归属与本次集成的关系
数据安全自研（防泄漏 / 加密 / 外设管控）不受影响，仅共享 UI 壳与采集管道
桌面管控自研不受影响
网络管理自研（零信任客户端 / SWG）不受影响
安全防护本次集成 安天 AV 引擎（病毒查杀 / 实时防护）AV 引擎为该模块核心检测源之一
风险运营自研（与管侧 Agentic SOC 联动）消费 AV / AIDR 产出的统一事件
AI Agent 防护本次集成 方寸 AIDR SDK（L2 推理 / L3 工具调用 / L4 数据检测响应）与自研 Supervisor、Rustinel 同模块协同

1.2 方寸 AIDR：能力与接口形态

维度事实 / 设计假设
能力范围AI 应用与 Agent 运行时检测响应：Prompt 注入检测、工具调用风险识别（L3）、敏感数据外发识别（L4）、风险会话抑制
交付形态本地 SDK（C/C++ 动态库）+ 模型/策略包文件 + 本地检测服务；推理可本地或近端
集成接口检测 API（同步调用）、事件回调（异步通知）、策略/模型加载 API、会话上下文注入接口
产出形态回调返回检测结果（风险等级 / 类别 / 证据），可适配为 JSONL 告警文件落盘
关联键session_id / trace_id，与网关侧 AI 全链路跟踪审计共用链路 ID
AIDR 检测是「调用式」的：由 AI Agent 防护模块的会话采集点（网关代理 / 本地代理）触发检测调用，AIDR SDK 返回判定 → 适配器转事件 → 文件交付。这与 AV 的「引擎自主扫描」不同，指令面以策略下发为主、任务型指令少。

1.3 安天 AV：能力与接口形态

维度事实 / 设计假设
能力范围病毒查杀（按需扫描 / 实时防护）、隔离区、白名单、特征库升级；移动端病毒防护能力可补齐防火墙侧规划差距项
交付形态引擎库（DLL / so）+ 特征库文件 + 可选内核 minifilter 驱动（实时防护）
集成接口扫描 API（同步 / 异步）、实时防护回调、隔离区管理 API、特征库升级 API、引擎配置
产出形态扫描结果报告（任务型，整文件）、病毒事件即时通知（回调）、引擎运行日志
授权形态按终端授权（授权文件 / 许可证），特征库升级需凭证校验
AV 是「引擎自主 + 任务驱动」型：实时防护由驱动/回调持续触发，按需扫描是典型长任务（分钟~小时级），指令面以任务型指令为主，必须有任务句柄 / 进度 / 取消 / 限速模型。

1.4 集成约束

约束说明设计响应
闭源二进制两个 SDK 均为闭源库，无法审计内部行为，崩溃 / 泄漏 / 兼容问题只能隔离不能修复进程边界隔离 + 崩溃自动重启 + 独立 dump 收集
授权与合规SDK 授权文件、升级凭证是敏感资产凭证由 Agent Core 统一保管，适配进程按需领取，不落明文配置
性能不可控全盘扫描 / 模型推理资源占用由引擎决定进程级 CPU/IO 配额（Job Object / cgroups）+ 平台可下发限速
版本演进SDK 会独立升级，接口可能不兼容适配进程独立升级 + 契约版本协商（HELLO 中报 contract_ver）
驱动级协同AV 实时防护需要内核驱动配合，驱动与引擎库可能强绑定驱动层例外：允许驱动直接通知适配进程；引擎库本身仍不进宿主

02集成形态决策：适配进程隔离

核心决策：SDK 进程内加载（in-process）与独立适配进程加载（out-of-process）的六切面对比，结论是一律 out-of-process。
切面in-process（宿主进程直接加载 SDK）out-of-process（独立适配进程加载 SDK）
崩溃隔离SDK 崩溃 = 统一客户端整体崩溃，防护全下线适配进程崩溃可自动重启，宿主与其它插件不受影响
资源泄漏闭源库内存/句柄泄漏直接拖垮宿主，无法定位进程边界兜底，泄漏可观测（进程指标）可定点重启
性能开销无 IPC 开销有 IPC 开销，但日志走文件交付零 IPC、指令低频，实测影响可忽略
独立升级SDK 升级必须重启宿主进程，防护中断适配进程独立升级 / 重启，防护面其余部分不中断
调试定位宿主崩溃 dump 混杂三方符号，责任难界定独立 dump 独立符号，厂商责任边界清晰
多引擎扩展第二个引擎进来重复承担全部风险新增引擎 = 新增一个适配进程，宿主零改动
决策结论（P0）：统一客户端宿主进程（UI / Agent Core）永不加载任何第三方 SDK。每个第三方 SDK 对应一个独立适配进程，由 Supervisor 托管。唯一例外是 AV 内核驱动（实时防护必需），驱动与适配进程直连，宿主与 UI 仍不接触。
代价与接受理由：多两个常驻进程（约 30~80MB 内存 / 进程，取决于引擎）。相比 in-process 的「一次崩溃全下线 + 升级必重启 + 责任不可分」，这是值得付出的代价；且适配进程可按平台画像配置为按需拉起（如仅启用 AV 时才拉起 AV 适配进程）。

04适配层设计：契约映射

适配进程是 SDK 与统一客户端之间唯一边界。对外实现统一插件契约（见《落地方案设计》第 3 章 C1~C12），对内封装 SDK 私有 API。

4.1 契约维度映射表

契约维度统一要求AV 适配器实现AIDR 适配器实现
注册声明双层注册：安装时 plugin_config.jsonc 静态声明（4.4 节），运行时 HELLO 上报 plugin_id / 版本 / 能力集 / contract_ver，两处不一致以保守者为准AppID=com.h3c.sec.avadapter，能力：scan / rtp / quarantine / whitelist / updateAppID=com.h3c.sec.aidradapter，能力：detect / policy / inhibit
数据交付只写本地文件，不自建上报通道（C5）病毒事件 JSONL + 扫描报告整文件 + 引擎日志检测告警 JSONL + 检测统计快照
指令响应收到 CMD 回 ACCEPTED，异步回 RESULT扫描/升级/隔离/白名单五类指令策略下发 / 模型更新 / 抑制窗口三类指令
状态快照周期整写状态文件（供 UI 与画像）病毒库版本 / 最近扫描时间 / 隔离数 / 实防开关模型版本 / 策略版本 / 最近检测统计 / 抑制状态
配置管理CONFIG_SET 指令 + 本地配置文件扫描线程数 / 排除路径 / 实防开关 / 限速检测阈值 / 场景开关 / 采样率

4.2 回调桥接模式（两个适配器共用）

两个 SDK 都以回调推事件。回调发生在 SDK 内部线程，适配器在回调内只做最轻动作，否则可能阻塞引擎内部队列：

// 适配器回调桥接：回调线程只入内存队列，落盘由独立写线程完成
func (a *Adapter) OnEvent(raw SdkEvent) {
    select {
    case a.ch <- raw:            // 有界队列 4096，满则丢弃并计数（丢弃计数进心跳）
    default: a.dropped.Add(1)
    }
}

func (a *Adapter) writerLoop() {
    for ev := range a.ch {
        line := envelope.Normalize(ev)          // 转统一事件信封（第 09 章）
        a.jsonl.Append(line)                    // 追加写 JSONL，采集器接管后续
    }
}
这一层保证「SDK 事件 → 文件」的转换是唯一需要适配器写代码的地方；文件之后的读取、缓冲、上报全部复用《日志采集专项设计》的统一采集器，两个适配器不重复造轮子。

4.3 SDK 私有 API 封装原则

原则说明
不外溢SDK 头文件 / 类型只在适配进程代码中出现；契约消息体（Protobuf）不含任何 SDK 类型
可替换适配器内对 SDK 调用做一层薄包装（接口 + 实现），换 SDK 版本只改实现文件
失败兜底SDK 初始化失败 → 适配进程进入 degraded 状态并在状态快照标明，Supervisor 按 C8 策略告警但不拖垮整体
授权解耦授权文件路径 / 升级凭证由 Supervisor 通过启动参数或受控文件注入，适配器不硬编码、不缓存明文

4.4 声明式插件配置（对齐 iNode plugin_config.jsonc）

采纳 iNode 插件系统的声明式配置规范作为统一客户端插件包标准：每个插件包必须包含 plugin_config.jsonc，安装时静态验证，运行期不再依赖。在 iNode 五个区块基础上扩展 Security 与 DataSources 两个统一客户端必需区块：

区块字段要点与 iNode 指南的关系
PluginInfo（必填）AppID（反向域名格式）/ DisplayName / Type（ui | background | mix）/ Version / Icon / Description原样采纳；AppID 强制反向域名（第三方适配器统一 com.h3c.sec.* 前缀）
Frontend（ui/mix 必填）Binary / Params / Width / Height（默认窗口尺寸）原样采纳；Width/Height 作为统一客户端窗口宿主的尺寸协商值
Backend（background/mix 必填）Binary / Params原样采纳；AV / AIDR 适配进程即 Backend
Runtime（可选）AutoLoad / StartDelay / StopTimeout原样采纳，语义映射见第 05 章
Installation（可选）RequireAdmin / DataPath / LogPath / RebootRequired原样采纳；LogPath 成为采集源自动注册锚点（7.4 节）
扩展 Security（必填）Signature（minisign 签名文件路径）/ Capabilities（network 声明、privileged_ops 声明）/ ContractVer（插件契约版本）统一客户端新增：无此区块拒绝安装
扩展 DataSources（可选）events / alerts / status / log 四类文件相对路径 + schema 名统一客户端新增：声明即注册进采集 Source Registry（7.4 节）

AV 适配进程的完整配置示例：

{
  "PluginInfo": {
    "AppID": "com.h3c.sec.avadapter",
    "DisplayName": "病毒防护（安天引擎）",
    "Type": "background",                    // 适配进程无自带界面
    "Version": "3.2.1",
    "Description": "病毒查杀 / 实时防护 / 隔离区，引擎能力封装"
  },
  "Backend": {
    "Binary": "bin/av_adapter.exe",
    "Params": "--contract=v1"
  },
  "Runtime": {
    "AutoLoad": true,                        // 安全防护模块启用即随客户端启动
    "StartDelay": 800,                       // 引擎加载较重，错峰于自研插件
    "StopTimeout": 10000                     // 防护类进程优雅退出给足 10s
  },
  "Installation": {
    "RequireAdmin": true,                    // minifilter 驱动安装需要
    "DataPath": "./data",
    "LogPath": "./logs",
    "RebootRequired": true
  },
  "Security": {                              // 【扩展区块】统一客户端必填
    "Signature": "sig/plugin.manifest.sign",
    "Capabilities": {
      "network": ["update.av.h3c.com:443"],  // 出网目标白名单，唯一例外
      "privileged_ops": ["minifilter"]
    },
    "ContractVer": "1.0"
  },
  "DataSources": {                           // 【扩展区块】声明即被采集器接管
    "events":  { "path": "data/threat_events.jsonl", "schema": "av.threat.v1",      "priority": "P0" },
    "reports": { "path": "data/reports/*.json",      "schema": "av.scan_report.v1", "priority": "P1" },
    "status":  { "path": "data/status.json",         "schema": "av.status.v1",      "priority": "P2" },
    "log":     { "path": "logs/",                    "mode": "log-sampler" }
  }
}
DataSources 声明与 supervisor.toml 静态配置合并注册，静态配置优先于插件声明（沿用日志采集专项设计的冲突仲裁规则）——第三方适配器随包自带声明即可工作，平台侧仍可强制覆盖。契约消息与采集配置中的 plugin_id 沿用短名（av-antian / aidr-fc），安装登记时与 AppID 建立映射，避免长反向域名在 IPC 与事件流中膨胀。

4.5 插件自治与安全基线的边界

iNode 指南主张插件「完全独立、自己决定网络通信与端口」。统一客户端保留插件自治的开发便利，但按终端安全产品基线收紧三处：

维度iNode 原则统一客户端约束
工作方式 / 内部状态插件自治保留自治（AV / AIDR 引擎内部调度不干预）
开发技术栈任意可编译为可执行文件的技术保留自治，但必须通过安装验签（10.1 节）
网络通信自治（自己决定）收紧：出网目标必须在 Security.Capabilities.network 白名单声明，本地防火墙规则只放行声明目标，回环以外默认拒绝
数据上报无约束收紧：禁止自建上报通道，数据交付只走文件（契约 C5），网络仅用于特征库 / 模型升级一类白名单场景
端口 / IPC自治收紧：监听端口须在 Capabilities 声明并纳入审计；与宿主的 IPC 由契约固定（Named Pipe / UDS）
前端窗口独立 GUI 进程自带窗口调整：ui / mix 前端由统一客户端窗口宿主承载（6.6 节），不出现游离于统一 UI 之外的窗口
收紧的理由：iNode 是通用插件宿主，插件可信边界由用户安装行为保证；统一客户端的插件承载的是安全检测能力本身，一旦插件被仿冒或被植入上报通道，等于在防护核心上开洞 —— 自治性与安全基线冲突时，一律取安全基线。

05进程生命周期与守护

Supervisor 对两个适配进程的托管策略：拉起 / 崩溃重启 / 资源兜底 / 降级。
场景Supervisor 行为
启动编排对齐 iNode Runtime 字段：AutoLoad=true 且平台画像启用该模块 → 随客户端启动自动拉起；StartDelay 控制错峰（引擎加载较重的 AV 默认 800ms，晚于自研插件）；未启用模块的适配进程不占资源
崩溃重启指数退避（1s/5s/30s/5min 封顶）；5 分钟内崩溃 ≥3 次 → 进入熔断：停止重启、上报 P1 事件、状态卡标「故障」
假死检测心跳超时 90s 且状态文件无更新 → SIGTERM；再超时 30s → 强杀重启
资源兜底Windows Job Object / Linux cgroups 限制单适配进程内存上限（AV 1.5GB / AIDR 2GB，含模型加载），超限由 Supervisor 决定重启而非坐视系统 OOM
降级运行AV 适配进程不可用而 AIDR 正常 → 客户端整体降级运行，状态卡明确展示；绝不允许「静默半防护」
优雅退出卸载 / 升级前 SIGTERM，适配器完成 SDK 反初始化（隔离区句柄 / 驱动通道）后再退出；超时取 plugin_config 的 StopTimeout（iNode 默认 5000ms，防护类进程建议 10000ms），超时强杀
驱动例外项：AV minifilter 驱动随引擎生命周期装卸，由适配进程通过授权服务接口控制；Supervisor 不直接操作驱动，驱动异常由适配器转译为状态快照字段上报。

要点设计

约定项iNode 指南统一客户端落地
日志目录LogPath 相对插件安装目录同路径；插件无需向宿主额外报路径，采集器按插件目录 + LogPath 推导
文件命名{AppID}_{日期}.log 按日轮转直接兼容：file_key 用 File ID / inode，按日轮转不丢位点（专项设计 05 章）
日志格式[时间] [级别] Message | Key: Value 文本格式双轨：业务/事件数据必须 JSONL（结构化信封）；运行日志允许 iNode 文本格式，LogSampler 做文本解析降级（级别行数统计 / 错误码 TopN 照常可用）
stdout / stderr管理器捕获并记入管理器日志Agent Core 将适配进程 stdout/stderr 重定向到 {LogPath}/console.log，走运行日志路径（摘要 + 事件触发快照 + LOG_FETCH）
自动注册—（指南无采集概念）新增：插件安装成功后，采集器按 LogPath 自动注册一条 LogSampler 源 + 按 DataSources 声明注册业务源，无需手写 supervisor.toml
iNode 指南只覆盖「日志写在哪、什么格式」，未覆盖「谁读、怎么传、断了怎么办」——这一段正是统一客户端契约与专项设计的增量：路径格式对齐 iNode 降低插件开发成本，传输与可靠性由统一采集器兜底。

一条链路、一个信封、一张指令目录。平台下发与 UI 本地操作共用同一 CMD 通道与审计视图。

平台 / UI
   │  WSS 下行（平台）或 POST /cmd（UI）

10.1 插件包规范与安装流程（对齐 iNode）

采纳 iNode 的 ZIP 打包结构与安装流程，并在「验证配置」与「登记」两步之间强制插入验签：

av_adapter.zip
├── plugin_config.jsonc       # 配置文件（必需，含 Security 扩展区块）
├── bin/                      # 可执行文件目录（至少一个）
│   ├── av_adapter.exe        # Backend（适配进程）
│   ├── avl_engine.dll        # 安天引擎库（三方 SDK 交付物）
│   └── vc_redist/            # 运行时依赖
├── sig/
│   └── plugin.manifest.sign  # minisign 签名（必需，Security.Signature 指向）
├── assets/                   # 初始特征包 / 模型包（可选）
└── icon.png                  # 图标（可选）
步骤动作失败处理
① 解压用户/平台触发安装，Agent Core 解压至 plugins/{AppID}/目录冲突：比对版本，低版本拒绝覆盖安装
② 验签SHA-256 完整性 + minisign 签名校验（对齐 Rustinel rules install 机制），拒绝无签名 / 验签失败包拒绝安装并上报审计事件
③ 验证配置plugin_config 结构校验（iNode 规则：Type 与 Frontend/Backend 至少一个匹配、bin 至少一个可执行）+ Security 区块必填 + DataSources 路径白名单校验（禁越出插件目录）拒绝安装并给出明确原因码
④ 登记写本地登记库（AppID / Version / 能力集 / DataSources / 灰度组）；RequireAdmin=true 则此步在提权安装事务内完成；RebootRequired=true 标记重启待办并 UI 提示回滚解压目录，登记失败不留半装态
与 iNode 指南的差异：iNode 安装流程为「解压 → 验配置 → 登记」，信任用户选择；统一客户端在中间强制验签，且 DataSources 声明的路径必须收敛在插件目录内（防止声明 ../../ 类路径劫持采集器）。

10.2 资产升级通道

资产升级通道频率失败处理
AV 病毒库平台下发 UPDATE_LIB 或终端定时拉取（凭证由 Agent Core 注入）小时级保留旧库继续防护 + 状态卡降级原因 + 重试退避
AV 引擎库适配进程整包升级（ Supervisor 停旧进程 → 换包 → 拉新）月级升级前校验签名；失败回滚旧包
AIDR 模型包MODEL_UPDATE 指令下发，包签名校验周级双包共存，加载失败自动回旧模型，服务不中断
AIDR 策略包POLICY_PUSH，版本号管理天级失败保持旧策略 + degrade_reason 展示
适配进程自身随统一客户端插件升级机制（灰度 1% → 10% → 100%）季级灰度期崩溃率 / 事件量监控，异常自动暂停放量
签名校验规则对齐 Rustinel 的 rules install/update 机制（SHA-256 + minisign），第三方资产包统一走同一套签名与校验实现。

11安全与权限

风险面措施
本地 API 被滥用仅 127.0.0.1 回环 + 每次启动轮换的本地 token；高危操作（隔离恢复 / 白名单）要求本地管理员口令
IPC 伪造指令命名管道 / UDS ACL 限定进程身份；CMD 信封带时间戳与序列号防重放（对齐 OBO/mTLS 防重放思路）
SDK 升级劫持所有资产包（病毒库 / 模型 / 策略 / 引擎）强签名校验，拒绝无签名或验签失败包
授权凭证泄漏凭证 Agent Core 内存保管 + 受控注入，适配进程不落盘明文；日志脱敏规则覆盖凭证字段
隔离区逃逸隔离文件由引擎加密存放；RESTORE 指令需平台或本地双因素之一，且全程审计
UI 提权UI 进程低权限运行；一切需提权的操作由 Agent Core 通过最小授权服务代理完成

12资源控制与共存

12.1 资源配额与模式抑制

机制设计
进程配额Windows Job Object / cgroups：AV 适配进程 CPU ≤ 40%（可被 CONFIG_SET 下调）、内存 1.5GB；AIDR 内存 2GB（含模型）
扫描限速全盘扫描默认低 IO 优先级 + 可配置 IOPS 上限；用户主动发起的扫描提升优先级
模式抑制游戏 / 演示 / 会议模式（UI 一键或平台下发）：暂停全盘扫描、AI 检测降采样、toast 静默，实时防护保持
升级错峰病毒库与模型包升级全局排队，默认业务低峰（画像学习各终端空闲时段）

12.2 与第三方 AV 共存

场景策略
检测到第三方 AV安天引擎默认进被动模式（仅按需扫描 / 不装 minifilter），UI 状态卡明示「被动模式」
平台策略覆盖平台可按终端组强制主防模式（替换决策在平台做，终端只执行）
卸载竞态第三方 AV 卸载后 10 分钟内完成主防模式切换并上报，切换期间状态卡显示过渡态

15风险与对策

风险等级对策
SDK 回调在高并发下丢事件或死锁高回调只入队；PoC 阶段压测回调吞吐（≥2000 事件/秒）并纳入阶段一出口条件
AV 引擎与国产 OS / 加密驱动冲突（minifilter 栈）高兼容性矩阵实测先行；冲突时自动降被动模式并上报
双 SDK 同时升级打满磁盘 IO中全局升级队列错峰 + IO 配额
模型包体积大，弱网终端升级失败率高中断点续传 + 差分包 + 双包共存回滚
UI 壳选型摇摆（原生 vs Electron）中阶段一先用极简原生壳验证协议层，UI 全量放阶段二，选型在 M1 结束时定
第三方 SDK 授权到期导致批量降级中平台侧授权到期监控，提前 30 天告警；终端降级原因透出
